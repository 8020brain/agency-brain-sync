Agency Brain · how it works

How your brain stays in sync,
and how the app updates itself.

Two quiet background jobs run the whole show. One keeps your team's files identical on everyone's machine. The other keeps the app itself current. They both happen to use GitHub, but they're separate systems on separate clocks, and that's the bit worth understanding.

You're seeing it from a team member's seat: you install once, then it just works.

You're seeing it from the Scout's seat: you set the agency up and look after it for everyone.

The one idea to hold onto

There are two different things called "GitHub" here, and almost all confusion comes from treating them as one. They are not.

System 1 · runs constantly

The sync (your files)

Keeps the shared brain folder identical on every teammate's machine.

  • Moves only tiny text files (notes, skills, context).
  • Talks to your team's private brain repo on GitHub.
  • Uses a temporary key, so it's safe to run every minute.
  • This is the part that made a new skill appear on the other machine.
System 2 · runs occasionally

The update (the app itself)

Replaces the Agency Brain program with a newer version when one ships.

  • Moves the whole 80MB app installer (only when there's a new one).
  • Talks to a different GitHub area: the app's releases.
  • That area is rate-limited, so it can't be checked every minute.
  • This is the part that shows the "Relaunch to update" toast.
Why the app can't just "know" about a new version on its own

The app only knows the version it's running. To find out a newer one exists, it has to look somewhere outside itself, every time. A file stored only on your computer can only ever repeat what the app already knows. So there's always one outside check. The only questions are where it looks and how often.

Picture a courier who, once a minute, pops to the depot: "anything new for my team? I'll take it." And whenever you've written something, after a short pause it gets driven over to everyone else. The depot is GitHub. The courier is the watcher.

The four clocks

People see a few different timers mentioned and assume they're competing. They're not. Three of them belong to the sync; one belongs to the update. Click each to expand.

Every 60 sec Pull — "anything new for me?" liveSync · the heartbeat tap to expand

Once a minute the watcher quietly asks the depot whether any teammate has pushed changes, and if so, pulls them straight down. This is why a new skill or note shows up on everyone's machine within about a minute.

It's a tiny, cheap request because the files are small text and it only downloads what actually changed.

~90 sec Push — send your changes out liveSync · after you edit something tap to expand

When you change a file, the watcher waits about 90 seconds of quiet before sending it out. That pause lets it batch a flurry of edits into one tidy update instead of firing on every keystroke.

So your own changes reach teammates a minute or two after you stop typing.

~1 hour Refresh the access key liveSync · keeps permission fresh tap to expand

The key the app uses to reach the brain repo is deliberately short-lived for security, so the watcher quietly fetches a fresh one about once an hour. You never see this.

It doubles as a heartbeat: each time it happens, the server notes that this machine is alive and connected. That's the connection dot in the roster. Note that it only means the app is running, not that the person is working. The roster shows that separately as "Activity", which only updates when someone actually pushes work they authored, so a machine left running quietly pulling everyone else's changes never looks active when it isn't.

Every 6 hours Is there a newer app? live today changingUpdate · a different system entirely tap to expand

This is the only clock that belongs to the update system, not the sync. Every six hours the app checks the releases area to see whether a newer version of Agency Brain itself has shipped. If one has, it downloads it in the background and shows the "Relaunch to update" toast.

Why six hours and not every minute: this check hits a part of GitHub that limits how often you can ask (roughly 60 requests an hour per office). A whole team checking every minute would trip that limit and get blocked. The file sync doesn't have this problem because it uses a different, keyed channel.

Coming soon planned

Six hours is slow. The plan is to check every 30 minutes and the moment you open the Command Centre, so in normal use you'd basically never wait. A later option is a tiny version file on our own server (no rate limit), checked on the 60-second sync beat for near-instant awareness. Both still only download the big installer when there's actually something new.

The safety stop (why it can pause)

The sync is deliberately careful. If your copy has unsent changes and teammates' changes have arrived that might collide, it stops and waits rather than risk overwriting anyone's work. It never silently throws away changes.

An example of a freeze, and the fix

One machine had a stray status file sitting in the folder that the app itself had generated. The watcher saw it as "unsent work", and since teammates' changes were also waiting, it played safe and paused. The fix was to tell the system to ignore that throwaway file, so the working folder reads as clean and the sync flows again.

As the Scout, if a member ever reports the menu bar saying it needs attention, that's this safety stop. It means "a human should glance at this", not "something broke".

FAQ for Owners and Scouts

Getting started

Do I have to use Cowork? Team
No but you'll probably want to check it out at least. Cowork, inside the Claude desktop app, is the simplest option and what most Team members use. You can also work in Claude Code in a terminal/IDE, or the Claude Code VS extension, whatever you prefer. As long as the Agency Brain app is running & Cowork/Code are working on the same folder, your work syncs the same way no matter which one you use.
I'm already running my brain solo in a terminal. If I move to Agency Brain but don't add anyone, does anything change?
No, and that's the point. Moving onto Agency Brain only makes sense if you want to bring team members in. If you're staying solo, just keep using /brain-update as you always have. The whole reason to upgrade is to become a team, and becoming a team means installing the GitHub App.
The wizard asked me to choose between "I already have a brain" and "start fresh from the template", with no recommended option. Which do I pick?
Both are fine; they suit different situations, so I deliberately don't steer you. "I already have a brain" (Path A) adopts your existing (solo) brain as the shared agency brain. It's the fastest and keeps all your work, but you have to get the sensitive-file step right before anyone joins. "Start fresh" (Path B) keeps your existing brain personal and creates a clean agency brain from the template, then copies across (if needed) only what you choose. It's the safest against leaks because the shared repo starts empty, but it's a bit more setup. Pick Path A if your brain is already tidy, Path B if you'd rather start the shared one clean.
I picked Path B (start fresh). What gets copied across, and does my existing brain get touched?
Claude copies across only the agency, client, and skill context you choose; you pick the categories. Anything sensitive stays out, so the shared brain starts clean, and your original personal brain is left exactly as it was. One thing to know: once the app switches to watching the new agency folder, it stops syncing your old personal brain. The done screen tells you this so it's not a surprise. Your old brain is safe and untouched, it's just no longer synced by this app.
The wizard says I'm not set up on my own GitHub repo yet. What do I do first?
Your brain needs to be on a private GitHub repo you own, because that's the repo the App syncs to the team. Run the pre-flight prompt from the Agency Brain page (https://m.ads2ai.com/agency-brain). It checks you're in your brain folder, looks at your git remotes, leaves the brain template alone, and if you don't have your own repo yet it creates a private one under your account and pushes your brain to it. Once that's done, go back to the wizard.
Where should I host the agency brain repo, my personal GitHub or a business account?
Use a GitHub organisation your business owns, not a personal account. In an org, the brain survives people coming and going: when someone leaves, you revoke their access and the org keeps everything, with nothing to transfer. A personal-account repo means a repo transfer every time the owner changes. I never host it for you and never create the org for you, but I'd strongly point you at setting one up.

Syncing & conflicts

How fast do changes sync between teammates? Team
The app saves and pushes your work about 60 to 90 seconds after you stop editing, and it pulls everyone else's latest about once a minute. So you're rarely more than a minute behind the rest of the team. You don't need to save or commit; the app handles all of it in the background.
What happens if two people edit the same file at the same time? Team
Nothing gets lost. The app keeps your version as the live one and drops your teammate's version right next to it with __from-remote added to the filename. You open both, keep the one you want, and delete the other. It's rare in practice, because people usually work on different files. If in doubt ask the brain to help you sort it out & ask you questions to decide what to keep from each file.
A teammate's change didn't sync, or I see a file with "__from-remote" in the name, or the app says it needs attention. How do I sort it out?
A few things could be going on. Team members can't write to the .claude/ folder, so if one of them edited a skill, the app set that change aside while everything else kept syncing. If two people edited the same file, the app keeps your version and drops theirs alongside with __from-remote in the name, so read both, keep one, delete the other. When the app wants you to look at something, the top of the tray menu says "Needs your attention" with a short reason: use "Discard my changes" in the app menu if you don't need your local edit, or open the file, resolve it, and save. Running the agency-tidy-up skill sweeps up leftover __from-remote and set-aside files. If in doubt just ask Claude to walk you through fixing it.

Privacy & data

Does the Owner, or Ads2AI/Mike see what I type? Team
No. The only thing recorded is a coarse line each time a skill runs: the time, the skill name, and potentially which client it was for. Your prompts, your conversation, and Claude's output are never logged. Per-person token usage is never tracked anywhere.
Where does our brain actually live? Is it on Ads2AI/Mike's servers? Team
No. Your agency hosts its own brain on its own GitHub, ideally an account your business controls. I (Mike) never host it for you and I never create a GitHub org for you. Your app just borrows short-lived access tokens that are created fresh for each sync and then expire.
I chose Path A. How do I keep client data and private notes out of the shared repo my teammates will see?
The upgrade prompt walks you through flagging each sensitive file. The files you flag get put in a private repo in your GitHub, and get removed from the agency repo. The Agency Brain App is not installed on that separate repo, so your teammates simply have no access to it. Do this before the first teammate joins, and be honest with yourself about what's sensitive, because anything that was committed to the agency repo earlier still sits in its history.
I told the prompt my brain has nothing private and skipped the sensitive-file step. Was that allowed?
Yes. Extracting sensitive files is strongly advised but you can skip it.
Isn't gitignoring a "personal" folder enough to keep client data private? Do I really need a separate repo?
For truly sensitive data, use the separate private repo. I don't fully trust the CLAUDE instructions to keep all sensitive files out of shared history 100% of the time so the separate repo is the best option. The gitignored personal folder is for routine local scratch files that just doesn't need sharing.
Can every Scout and Team member see every client's data in the shared brain? Is that a privacy problem?
Everyone who syncs reads everything, and that's by design. It mirrors how a Google Ads manager account works: the agency sees across all the accounts it manages. Roles control who can change things, not who can read them. If a specific client contract forbids the team seeing their data, the escape hatch is a separate private repo with its own access list, but that's an edge case rather than the normal setup.
How do I store Google Ads credentials so someone who leaves can't walk off with access?
Use the proxy model, which is the default. The real credentials live once on a service (eg Cloudflare) the Owner or Scout controls, and each team member holds only a revocable token, never the actual credentials. When someone leaves, you revoke their token in one place and you're done, with no need to re-key anything. The alternative, a credentials file on each machine, works for a small trusted team but puts a copy of the secret on every laptop (with no 2FA!), so the proxy model is the safer default.

Plans & seats

Where do I add Scouts and Team members, the website or the app?
The website (agency.ads2ai.com) is designed for the one-time setup: creating your team and installing the GitHub App. After that, everything to do with your roster, adding or removing Team members and swapping people between Owner and Scout, happens in the Command Centre (the app), not on the website.
I'm on the free Solo tier and couldn't add a 6th Team member. Is that a bug?
No, that's the cap working. The free Solo tier includes you plus up to 5 Team members. The team2 plan adds 2 Scouts & lifts the Team cap to 10, the 5-Scout tier to 25, and the 10-Scout tier to unlimited. If you've hit 5 team members and want more, just upgrade to the 'team2' plan.
Can I add a new Scout myself, or does that go through Ads2AI/Mike?
You can swap your existing people between Owner and Scout freely, because those two roles have identical access and it's really just a label. You also add and remove Team members yourself. But a brand-new Scout is a paid seat and a full Ads to AI membership, so that one comes through me (Mike). Tell me the person's name and email and I'll set them up. There's no self-serve new Scout.
If my Ads to AI membership lapses, what happens to my team's sync?
Syncing stops, because the GitHub App can no longer create the tokens each sync needs. Renew at ads2ai.com and it picks straight back up. Owners and Scouts need to be active Ads to AI members; Agency Brain comes with that membership and can't be bought on its own.

Troubleshooting

Cowork (Claude) says it can't see the files. How do I fix it? Team
You've most likely pointed it at the wrong folder. Check which folder the Agency Brain app is watching (the app shows it), then in Cowork browse to and pick that same folder. If Cowork and the app are looking at different folders, your work won't reach the team.
Who do I contact when something goes wrong with Agency Brain? Team
Your Scout or Owner first, not Anthropic. They set your agency brain up and can see the GitHub side of things. When you ask, grab a screenshot and the app log (Show log in the app menu) so they can see what happened.
My setup push was rejected with a "workflow scope" error. How do I fix it?
Run gh auth refresh -s workflow, then push again (switching the remote to SSH also works). Your brain ships a file in .github/workflows/, and GitHub won't let a GitHub CLI token push a workflow file without the workflow scope. The setup prompt now refreshes this scope for you before it pushes, so you shouldn't hit it, but if you ever do, that's the one-line fix.
I installed the GitHub App but my teammate still can't sync, or the app says my repo doesn't match. Why?
There are two common causes. The first is ordering: the GitHub App has to be installed and linked to your team before the desktop app flips into team mode, otherwise the first sync can't get a token. The second is more subtle. If you'd installed the Agency Brain App on your GitHub account before your team existed, clicking Save on GitHub's "configure existing installation" screen does not link it to your team. The fix is to run the install link scoped to your team: github.com/apps/agency-brain-sync/installations/new?state=<your-team-slug>. That properly links it, and sync starts working.
I want to add a teammate, but the button just shows a message instead of a form. What's wrong?
That's expected before you've upgraded. As a solo owner you're not on a team yet, so the add-member form has nothing to add people to. Instead of throwing an error, the Command Centre shows a nudge pointing you at the tray item "Connect to my agency team…". Run that, finish turning your brain into an Agency Brain ready for a team, and the add-member form starts working.

Syncing & conflicts

How fast do changes sync between teammates? Team
The app saves and pushes your work about 60 to 90 seconds after you stop editing, and it pulls everyone else's latest about once a minute. So you're rarely more than a minute behind the rest of the team. You don't need to save or commit; the app handles all of it in the background.
What happens if two people edit the same file at the same time? Team
Nothing gets lost. The app keeps your version as the live one and drops your teammate's version right next to it with __from-remote added to the filename. You open both, keep the one you want, and delete the other. It's rare in practice, because people usually work on different files. If in doubt ask the brain to help you sort it out & ask you questions to decide what to keep from each file.
A colleague said they made a change, but I don't see it. Why?
The app pulls the team's latest about once a minute or two, so give it a moment. If it still hasn't shown up, click the Agency Brain icon and check the top of the menu says it's syncing (and that the icon isn't greyed out), and that Cowork is pointed at the right folder. If it seems stuck, message your Scout or Owner.
Do I need to save or commit my work?
No. The app watches your folder, and about a minute and a half after you stop editing it quietly saves and shares your work with the team. There's no save or commit button for you to press.
I made an edit and it didn't sync, but my other changes did. What happened?
You probably edited something that only Owners and Scouts can change, like a skill or a config file. The app sets those changes aside instead of blocking everything else, so the rest of your work still went through. If you needed that change, ask a Scout to make it for you.

Privacy & data

Does the Owner, or Ads2AI/Mike see what I type? Team
No. The only thing recorded is a coarse line each time a skill runs: the time, the skill name, and potentially which client it was for. Your prompts, your conversation, and Claude's output are never logged. Per-person token usage is never tracked anywhere.
Where does our brain actually live? Is it on Ads2AI/Mike's servers? Team
No. Your agency hosts its own brain on its own GitHub, ideally an account your business controls. I (Mike) never host it for you and I never create a GitHub org for you. Your app just borrows short-lived access tokens that are created fresh for each sync and then expire.
What's the "personal" folder, and who can see it?
It's your own private scratch space for meeting notes, todos, and rough drafts. Only you can see it; it never syncs to the team, and even the Owner can't look inside. One important catch: because it never leaves your machine, it isn't backed up. If your laptop dies, it's gone. So for any work you can't afford to lose move it into a shared folder.
