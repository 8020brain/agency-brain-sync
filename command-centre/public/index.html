Agency Brain · how it works

      
How your brain stays in sync,
and how the app updates itself.

      
Two quiet background jobs run the whole show. One keeps your team's files identical on everyone's machine. The other keeps the app itself current. They both happen to use GitHub, but they're separate systems on separate clocks, and that's the bit worth understanding.


      

        
        
      

      
You're seeing it from a team member's seat: you install once, then it just works.

      
You're seeing it from the Scout's seat: you set the agency up and look after it for everyone.


      
The one idea to hold onto

      
There are two different things called "GitHub" here, and almost all confusion comes from treating them as one. They are not.

      

        

          
System 1 · runs constantly

          
The sync (your files)

          
Keeps the shared brain folder identical on every teammate's machine.

          
    
            
  • Moves only tiny text files (notes, skills, context).
    • 
            
  • Talks to your team's private brain repo on GitHub.
    • 
            
  • Uses a temporary key, so it's safe to run every minute.
    • 
            
  • This is the part that made a new skill appear on the other machine.
    • 
          

        

        

          
System 2 · runs occasionally

          
The update (the app itself)

          
Replaces the Agency Brain program with a newer version when one ships.

          
    
            
  • Moves the whole 80MB app installer (only when there's a new one).
    • 
            
  • Talks to a different GitHub area: the app's releases.
    • 
            
  • That area is rate-limited, so it can't be checked every minute.
    • 
            
  • This is the part that shows the "Relaunch to update" toast.
    • 
          

        

      

      

        
Why the app can't just "know" about a new version on its own

        
The app only knows the version it's running. To find out a newer one exists, it has to look somewhere outside itself, every time. A file stored only on your computer can only ever repeat what the app already knows. So there's always one outside check. The only questions are where it looks and how often.

      


      
The sync, step by step

      
You (the Scout) set this up once for the agency. After that it runs itself on every machine, including yours.

      
You did the first step once. Everything after it is automatic and you never touch it.

      

        
You create the agency brain
A private repository is set up for your team, and Agency Brain is given permission to read and write it on members' behalf.

        
You invite each team member
Each person gets an email with a 6-character code. That code is their one-time key to join.

        
You install Agency Brain and paste your codeEach member installs the app and pastes their code
The app swaps the code for permission, then downloads a fresh copy of the team's brain folder onto the machine.

        
A quiet watcher starts
From then on, a small background program (the "watcher") sits in the menu bar and keeps that folder in step with everyone else's, with no further action needed.

        
It just works
Make a change and teammates see it within a minute or two. They make a change and you see it. Nobody runs commands.

      

      
Picture a courier who, once a minute, pops to the depot: "anything new for my team? I'll take it." And whenever you've written something, after a short pause it gets driven over to everyone else. The depot is GitHub. The courier is the watcher.


      
The four clocks

      
People see a few different timers mentioned and assume they're competing. They're not. Three of them belong to the sync; one belongs to the update. Click each to expand.

      


        

          
            Every 60 sec
            Pull — "anything new for me?" liveSync · the heartbeat
            tap to expand
          
          

            
Once a minute the watcher quietly asks the depot whether any teammate has pushed changes, and if so, pulls them straight down. This is why a new skill or note shows up on everyone's machine within about a minute.

            
It's a tiny, cheap request because the files are small text and it only downloads what actually changed.

          

        


        

          
            ~90 sec
            Push — send your changes out liveSync · after you edit something
            tap to expand
          
          

            
When you change a file, the watcher waits about 90 seconds of quiet before sending it out. That pause lets it batch a flurry of edits into one tidy update instead of firing on every keystroke.

            
So your own changes reach teammates a minute or two after you stop typing.

          

        


        

          
            ~1 hour
            Refresh the access key liveSync · keeps permission fresh
            tap to expand
          
          

            
The key the app uses to reach the brain repo is deliberately short-lived for security, so the watcher quietly fetches a fresh one about once an hour. You never see this.

            
It doubles as a heartbeat: each time it happens, the server notes that this machine is alive and connected. That's the connection dot in the roster. Note that it only means the app is running, not that the person is working. The roster shows that separately as "Activity", which only updates when someone actually pushes work they authored, so a machine left running quietly pulling everyone else's changes never looks active when it isn't.

          

        


        

          
            Every 6 hours
            Is there a newer app? live today changingUpdate · a different system entirely
            tap to expand
          
          

            
This is the only clock that belongs to the update system, not the sync. Every six hours the app checks the releases area to see whether a newer version of Agency Brain itself has shipped. If one has, it downloads it in the background and shows the "Relaunch to update" toast.

            
Why six hours and not every minute: this check hits a part of GitHub that limits how often you can ask (roughly 60 requests an hour per office). A whole team checking every minute would trip that limit and get blocked. The file sync doesn't have this problem because it uses a different, keyed channel.

            

              
Coming soon planned

              
Six hours is slow. The plan is to check every 30 minutes and the moment you open the Command Centre, so in normal use you'd basically never wait. A later option is a tiny version file on our own server (no rate limit), checked on the 60-second sync beat for near-instant awareness. Both still only download the big installer when there's actually something new.

            

          

        


      


      
What happens when a new skill is added

      
This is the flow we watched work end to end.

      

        
You add a skill to the brainThe Scout adds a skill
A new skill folder appears in the shared brain.

        
The watcher pushes it (~90 sec)
After the short pause, that machine sends the new skill up to the depot.

        
Every other machine pulls it (~60 sec)
Within a minute, the skill folder lands on every teammate's computer.

        
The Command Centre shows it on next open
The skill count and list update when the Command Centre is reopened, so the count climbs for everyone.

      


      
What happens when a new app version ships

      

        
A new version is published
A signed Mac build and a Windows build are posted to the releases area, ready to download.

        
A new version is published
Behind the scenes, a newer Agency Brain is made available. You don't have to go looking for it.

        
Your app notices on its next check
On the update clock (today every 6 hours), the app spots the newer version.

        
It downloads quietly in the background
The installer comes down while you keep working. Nothing interrupts you.

        
"Relaunch to update" appears
When it's ready, a small toast offers a relaunch. Click it and you reopen on the new version. That's the only action you take.

      


      
The safety stop (why it can pause)

      
The sync is deliberately careful. If your copy has unsent changes and teammates' changes have arrived that might collide, it stops and waits rather than risk overwriting anyone's work. It never silently throws away changes.

      

        
An example of a freeze, and the fix

        
One machine had a stray status file sitting in the folder that the app itself had generated. The watcher saw it as "unsent work", and since teammates' changes were also waiting, it played safe and paused. The fix was to tell the system to ignore that throwaway file, so the working folder reads as clean and the sync flows again.

      

      
As the Scout, if a member ever reports the menu bar saying it needs attention, that's this safety stop. It means "a human should glance at this", not "something broke".

Agency Brain · updates

      
Two things update.
Only one of them is automatic.

      
The Agency Brain app keeps itself current on its own. Your agency's brain, the shared folder of skills and context your team works in, is deliberately never touched by an auto-updater: it's your team's work, so updating it is a decision you make. Here's how both work, and the one small routine worth adopting.


      

        

          
Automatic · nothing to do

          
The app (and this Command Centre)

          
    
            
  • The app checks for a new version every few hours, downloads it quietly in the background, and shows a "Relaunch to update" toast when it's ready.
    •

FAQ for Owners and Scouts

      

        
Getting started

        
Can I use my brain from my phone? Team
Partly, and the part that doesn't work is worth knowing before you rely on it.

**Cowork on a phone cannot reach your brain folder at all.** There's no route from the phone to your computer, so it can't read your files, and this is the bit that catches people: if you ask it to save something, it will tell you it's done. Nothing arrives. It wrote to its own temporary space, which disappears when the conversation ends. So treat Cowork on a phone as a good place to think out loud, and never as a place to do work on your brain.

**Claude Code on a phone works two different ways**, and only one of them touches your machine. A normal session there runs in the cloud on a copy of your repository, so it sees whatever your team has synced up, but nothing you haven't. Remote Control is the real thing: you start a session on your computer before you leave it, then join from your phone, and everything runs on your own machine exactly as if you were sat at it. Your phone is just acting as the keyboard. That's the one to use if you need to properly work while you're out, and the catch is that you have to set it going before you walk away.

        
Claude keeps stopping to ask permission for everything. Which mode should we use? Team
Turn on auto mode, it's what I recommend for everyone. In Cowork, use the mode selector next to the send button and pick Auto. In Claude Code, press Shift+Tab until the status bar says "auto mode on". Claude then gets on with the work instead of stopping to check every small step, while a built-in safety check reviews each action in the background and blocks anything risky, destructive, or aimed outside your own files. If Auto doesn't show up, update Claude Code or the Claude desktop app to the latest version; and if you're on a company Claude Team or Enterprise plan, an admin has to switch it on first in the organisation's Claude settings.

        
Do I have to use Cowork? Team
No but you'll probably want to check it out at least. Cowork, inside the Claude desktop app, is the simplest option and what most Team members use. You can also work in Claude Code in a terminal/IDE, or the Claude Code VS extension, whatever you prefer. As long as the Agency Brain app is running & Cowork/Code are working on the same folder, your work syncs the same way no matter which one you use.

        
I'm already running my brain solo in a terminal. If I move to Agency Brain but don't add anyone, does anything change?
No, and that's the point. Moving onto Agency Brain only makes sense if you want to bring team members in. If you're staying solo, just keep using /brain-update as you always have. The whole reason to upgrade is to become a team, and becoming a team means installing the GitHub App.

        
I already run a solo brain. Does the agency setup use it, or start fresh?
It starts fresh, always. The setup wizard creates a brand-new agency brain from the template in your own private GitHub repo, and your existing solo brain is left exactly as it was. Nothing is merged or overwritten. Once the agency brain is up, run the migration prompt on the Install page (https://m.ads2ai.com/agency-brain/install) to copy across just the custom skills and client folders you want. It treats your old brain as read-only and shows you a plan before it copies anything. (If the wizard ever asks you "do you already have a brain on this machine?", that's the solo setup path, not the agency one.)

        
I set up a fresh agency brain. What gets copied across from my old one, and does it get touched?
Claude copies across only the agency, client, and skill context you choose; you pick the categories. Anything sensitive stays out, so the shared brain starts clean, and your original personal brain is left exactly as it was. One thing to know: once the app switches to watching the new agency folder, it stops syncing your old personal brain. The done screen tells you this so it's not a surprise. Your old brain is safe and untouched, it's just no longer synced by this app.

        
The wizard says I'm not set up on my own GitHub repo yet. What do I do first?
That message only appears in the solo setup (adopting a brain you already have). Your brain needs to be on a private GitHub repo you own. Run the Update prompt from your setup guide (https://m.ads2ai.com/install); it checks you're in your brain folder, looks at your git remotes, and if you don't have your own repo yet it creates a private one under your account and pushes your brain to it. Then come back to the wizard and pick the folder again. Agency owners never hit this: the agency wizard creates the repo for you when you connect GitHub.

        
Does the agency brain have to go on a GitHub organisation, or can I use my personal account?
It has to be an organisation. That is GitHub's rule rather than mine: GitHub does not allow apps to create repositories on a personal account, only inside an organisation. So if you point setup at your personal account, nothing gets created and the screen sits there waiting.

Creating a free organisation takes about a minute at https://github.com/account/organizations/new. The free plan is all this needs, so never pay for one. Name it after the business. If GitHub asks who the organisation belongs to, "My personal account" is a fine answer. On the "Start collaborating" screen, click "Skip this step". GitHub's own walkthrough is here if you want it: https://docs.github.com/en/organizations/collaborating-with-groups-in-organizations/creating-a-new-organization-from-scratch

An organisation is the better home anyway. The brain survives people coming and going, because when someone leaves you revoke their access and the organisation keeps everything, with nothing to transfer. A repo on a personal account means a GitHub repo transfer every time the owner changes. I never host the brain for you and I never create the organisation for you, but that one minute is worth it.

        
Setup sat on "creating your brain" and nothing happened. What now?
Nine times out of ten, GitHub landed on a personal account instead of an organisation, and GitHub will not let an app create a repository there. Nothing is broken and nothing is lost.

First, update the Agency Brain app. Right-click the menu-bar or system-tray icon, click "Check for updates", then click "Relaunch now" in the box that appears. Recent versions check the organisation name with GitHub while you are still in the app, so they catch this before you go anywhere and tell you in plain words what is wrong.

Then create a free organisation at https://github.com/account/organizations/new if you do not already have one, and run setup again, giving it the organisation name. The other thing that can hold it up is the app already being installed on that organisation, in which case GitHub only offers you a "Configure" button, which never reports back. The current setup screen handles that case too.

      

      

        
Syncing & conflicts

        
How fast do changes sync between teammates? Team
The app saves and pushes your work about 60 to 90 seconds after you stop editing, and it pulls everyone else's latest about once a minute. So you're rarely more than a minute behind the rest of the team. You don't need to save or commit; the app handles all of it in the background.

        
What happens if two people edit the same file at the same time? Team
Nothing gets lost. The app keeps your version as the live one and drops your teammate's version right next to it with __from-remote added to the filename. You open both, keep the one you want, and delete the other. It's rare in practice, because people usually work on different files. If in doubt ask the brain to help you sort it out & ask you questions to decide what to keep from each file.

        
Can I keep big files like videos or design files in the brain folder? Team
The brain is built for text: notes, context, docs, and data files. Anything 50 MB or bigger doesn't sync, because GitHub (the service that moves changes between machines) rejects very large files outright, and one of them baked into a save can freeze syncing for the whole brain. The app protects you from that automatically: it sets big files aside and keeps them on your machine only (the tray shows them as changes set aside), it blocks oversized saves even when Claude or a terminal is doing the committing, and if one sneaks in anyway it quietly unpicks it and keeps everything else syncing. Keep videos, design files, and big exports in Drive or Dropbox and put the share link in the brain instead. The link syncs; the two-gigabyte video never has to.

        
A teammate's change didn't sync, or I see a file with "__from-remote" in the name, or the app says it needs attention. How do I sort it out?
A few things could be going on. Team members can't write to the .claude/ folder, so if one of them edited a skill, the app set that change aside while everything else kept syncing. If two people edited the same file, the app keeps your version and drops theirs alongside with __from-remote in the name, so read both, keep one, delete the other. When the app wants you to look at something, the top of the tray menu says "Needs your attention" with a short reason: use "Discard my changes" in the app menu if you don't need your local edit, or open the file, resolve it, and save. Running the agency-tidy-up skill sweeps up leftover __from-remote and set-aside files. If in doubt just ask Claude to walk you through fixing it.

        
What if a team member changes or deletes files they shouldn't have? Should I set up pull requests or branch protection?
No gates, and that's deliberate. Every change anyone makes is recorded in your GitHub commit history, which works as an unlimited undo button. If someone overwrites or deletes a client's context, a Scout just asks the brain to restore it ("bring back the client file that got deleted this morning") and the files are back in a few minutes, without touching anyone else's work. Because recovery is that easy, I didn't want to add pull requests, branch protection, or approval steps that everyone has to jump through in the right order. Team members just edit; they don't save, commit, push, or wait for a review, and that simplicity is a big part of why they actually use it.

Worth knowing: if a file does get deleted, the deletion syncs to the whole team like any other change, so the fix is a rollback, not a hunt through backups. In practice it's rare. Team members work in Cowork, so they're not looking at a file tree the way you would in an IDE, and Claude itself pushes back on destructive commands. If the worst happens, the Scout saves the day; nothing is ever really lost.

      

      

        
Privacy & data

        
Does the Owner, or Ads2AI/Mike see what I type? Team
No. The only thing recorded is a coarse line each time a skill runs: the time, the skill name, and potentially which client it was for. Your prompts, your conversation, and Claude's output are never logged. Per-person token usage is never tracked anywhere.

        
Where does our brain actually live? Is it on Ads2AI/Mike's servers? Team
No. Your agency hosts its own brain on its own GitHub, ideally an account your business controls. I (Mike) never host it for you and I never create a GitHub org for you. Your app just borrows short-lived access tokens that are created fresh for each sync and then expire.

        
We have thousands of documents in Google Drive. Do they go in the brain?
Only a small slice of them. Import the written-down explanations of how the business works (SOPs, price lists, brand and voice docs, proposals), because that is what context files are made of and it changes slowly. Leave everything live and large in Drive, and link to it instead: each person connects their own Google account at claude.ai under Customize then Connectors, and Claude can then read whatever that person can already open. Connectors set up there work in Claude Code as well as Cowork. Then keep a short index in the brain naming the main folders and what each is for, so the brain knows what exists without opening anything.

The reason to link rather than copy is not tidiness. A brain is a git repository, so anything committed stays in the history on every machine that ever syncs it, and you could not honour a deletion request without rewriting that history everywhere. Linked documents never enter the repo at all.

The full version of this, including the client-facing caveats and what to do for a Microsoft business, is on the Client Brain tab under "My client has thousands of documents in Google Drive".

        
How do I keep client data and private notes out of the shared repo my teammates will see?
The agency brain starts clean from the template, so nothing of yours is in it until you put it there. Two habits keep it that way. First, when you run the migration prompt to bring things across from your solo brain, leave out anything sensitive; it only copies what you approve. Second, anything that should never be visible to the team (financials, salaries, sensitive client notes) belongs in your separate owner-private repo, which the Agency Brain App is not installed on, so your teammates simply have no access to it.

        
Isn't gitignoring a "personal" folder enough to keep client data private? Do I really need a separate repo?
For truly sensitive data, use the separate private repo. I don't fully trust the CLAUDE instructions to keep all sensitive files out of shared history 100% of the time so the separate repo is the best option. The gitignored personal folder is for routine local scratch files that just doesn't need sharing.

        
Can every Scout and Team member see every client's data in the shared brain? Is that a privacy problem?
Everyone who syncs reads everything, and that's by design. It mirrors how a Google Ads manager account works: the agency sees across all the accounts it manages. Roles control who can change things, not who can read them. If a specific client contract forbids the team seeing their data, the escape hatch is a separate private repo with its own access list, but that's an edge case rather than the normal setup.

        
How do I store Google Ads credentials so someone who leaves can't walk off with access?
Use the proxy model, which is the default. The real credentials live once on a service (eg Cloudflare) the Owner or Scout controls, and each team member holds only a revocable token, never the actual credentials. To start, the whole team shares one token; when someone leaves you rotate that token and re-share it with whoever stays. If you'd rather remove one person without re-keying everyone, there's an optional per-person mode where each person has their own token and you revoke just theirs (one person administers that token list, on one machine). The alternative, a credentials file on each machine, works for a small trusted team but puts a copy of the secret on every laptop (with no 2FA!), so the proxy model is the safer default.

        
Who can create or revoke the Google Ads access tokens?
By default the whole team shares one token, so there's nothing to administer: to remove someone you rotate that shared token and re-share it with whoever stays. If you switch on the optional per-person tokens (so you can revoke one person at a time), then exactly one person administers them, usually whoever set the vault up. That per-person token list lives only on that one machine and can't be read back from the server, so a second person issuing tokens from a different machine would wipe everyone else's (the tool now refuses that unless it's a brand-new vault). So pick one token administrator and keep it with them. Worth knowing either way: the server accepts any valid token from anywhere, so keeping tokens inside your team is a rule you enforce, not something the server blocks.

Troubleshooting

        
Cowork (Claude) says it can't see the files. How do I fix it? Team
Three things cause this, and they look identical from where you're sitting, so check them in this order.

**Is the Claude desktop app open?** Cowork does its thinking on Anthropic's servers and reaches your machine through that app, so if the app is closed, or it quit in the background, or your machine slept, your files are simply out of reach. Cowork then tells you it can't find them. That's the same wording you'd get if the file really had been deleted, which is what makes this one so confusing. Open the app and ask again.

**Is it the same folder?** Check which folder the Agency Brain app is watching (the app shows it), then in Cowork browse to and pick that same folder. If Cowork and the app are looking at different folders, your work won't reach the team.

**Did it answer, but with something out of date?** This one has no error at all, so it's the one to watch for. Cowork keeps its own copy of files it has already read, and that copy sticks around after the connection to your machine drops. It will quote the old version straight back to you, sounding completely sure. If an answer doesn't match what you know is in the file, open the desktop app, then start a fresh Cowork conversation rather than carrying on in the old one.

The rule underneath all three: "I can't find it" from Cowork means "I can't reach it", and that is not the same as the file being gone. Your files are on your machine and in your team's history the whole time.

        
Cowork won't start on Windows. It says "Missing HCS Services: HNS, vmcompute". What now? Team
That message means the PC is running Windows Home, which can't run Cowork at all. Cowork does its work inside a small virtual machine, and the Windows features it needs (the Hyper-V stack) only ship with Windows Pro, Enterprise, or Education. There's no reliable settings or PowerShell fix on Home.

Three ways forward, cheapest first. One: use Claude Code instead. It runs fine on Windows Home, works on the Claude plan you already have, and points at the same brain folder, so everything syncs exactly the same; all you give up is Cowork's visual layout. Two: upgrade Windows from Home to Pro (a one-off US$99 licence upgrade from Microsoft, no new computer needed), and Cowork then runs on the machine as normal. Three: a Claude Max plan includes Cowork in the browser, which runs in the cloud and skips the Windows problem entirely, but it's the priciest option and the other two are usually the better call.

        
The app says it "can't push your changes up". Is my work lost? Team
No, nothing is lost. That message means your work is safely saved on your machine, but the app couldn't hand it up to GitHub on its last attempt. It keeps retrying every minute or so, and most of the time the cause is a brief internet blip or two teammates saving at the same moment, which clears itself within a few minutes. If it stays up for more than an hour, something real is in the way. First check the app is up to date (it updates itself within a few hours of a release), because current versions fix the common causes on their own, including a too-big file baked into a save. If it still won't clear, grab the app log (Show log in the app menu) and send it to your Scout or Owner, or get in touch with us; recent versions also report the underlying reason to us, so we can usually see exactly what's wrong from our side.

        
Who do I contact when something goes wrong with Agency Brain? Team
Your Scout or Owner first, not Anthropic. They set your agency brain up and can see the GitHub side of things. When you ask, grab a screenshot and the app log (Show log in the app menu) so they can see what happened.

        
My setup push was rejected with a "workflow scope" error. How do I fix it?
Run gh auth refresh -s workflow, then push again (switching the remote to SSH also works). Your brain ships a file in .github/workflows/, and GitHub won't let a GitHub CLI token push a workflow file without the workflow scope. The setup prompt now refreshes this scope for you before it pushes, so you shouldn't hit it, but if you ever do, that's the one-line fix.

        
I installed the GitHub App but my teammate still can't sync, or the app says my repo doesn't match. Why?
There are two common causes. The first is ordering: the GitHub App has to be installed and linked to your team before the desktop app flips into team mode, otherwise the first sync can't get a token. The second is more subtle. If you'd installed the Agency Brain App on your GitHub account before your team existed, clicking Save on GitHub's "configure existing installation" screen does not link it to your team. The fix is to run the install link scoped to your team: github.com/apps/agency-brain-sync/installations/new?state=<your-team-slug>. That properly links it, and sync starts working.

        
I want to add a teammate, but the button just shows a message instead of a form. What's wrong?
That's expected before you've upgraded. As a solo owner you're not on a team yet, so the add-member form has nothing to add people to. Instead of throwing an error, the Command Centre shows a nudge pointing you at the tray item "Connect to my agency team…". Run that, finish turning your brain into an Agency Brain ready for a team, and the add-member form starts working.

You open both, keep the one you want, and delete the other. It's rare in practice, because people usually work on different files. If in doubt ask the brain to help you sort it out & ask you questions to decide what to keep from each file.

        
Can I keep big files like videos or design files in the brain folder? Team
The brain is built for text: notes, context, docs, and data files. Anything 50 MB or bigger doesn't sync, because GitHub (the service that moves changes between machines) rejects very large files outright, and one of them baked into a save can freeze syncing for the whole brain. The app protects you from that automatically: it sets big files aside and keeps them on your machine only (the tray shows them as changes set aside), it blocks oversized saves even when Claude or a terminal is doing the committing, and if one sneaks in anyway it quietly unpicks it and keeps everything else syncing. Keep videos, design files, and big exports in Drive or Dropbox and put the share link in the brain instead. The link syncs; the two-gigabyte video never has to.

        
A colleague said they made a change, but I don't see it. Why?
The app pulls the team's latest about once a minute or two, so give it a moment. If it still hasn't shown up, click the Agency Brain icon and check the top of the menu says it's syncing (and that the icon isn't greyed out), and that Cowork is pointed at the right folder. If it seems stuck, message your Scout or Owner.

        
Do I need to save or commit my work?
No. The app watches your folder, and about a minute and a half after you stop editing it quietly saves and shares your work with the team. There's no save or commit button for you to press.

        
I made an edit and it didn't sync, but my other changes did. What happened?
You probably edited something that only Owners and Scouts can change, like a skill or a config file. The app sets those changes aside instead of blocking everything else, so the rest of your work still went through. If you needed that change, ask a Scout to make it for you.

Does the Owner, or Ads2AI/Mike see what I type? Team
No. The only thing recorded is a coarse line each time a skill runs: the time, the skill name, and potentially which client it was for. Your prompts, your conversation, and Claude's output are never logged. Per-person token usage is never tracked anywhere.

        
Where does our brain actually live? Is it on Ads2AI/Mike's servers? Team
No. Your agency hosts its own brain on its own GitHub, ideally an account your business controls. I (Mike) never host it for you and I never create a GitHub org for you. Your app just borrows short-lived access tokens that are created fresh for each sync and then expire.

        
What's the "personal" folder, and who can see it?
It's your own private scratch space for meeting notes, todos, and rough drafts. Only you can see it; it never syncs to the team, and even the Owner can't look inside. One important catch: because it never leaves your machine, it isn't backed up. If your laptop dies, it's gone. So for any work you can't afford to lose move it into a shared folder.

      

      

        
Troubleshooting

        
Cowork (Claude) says it can't see the files. How do I fix it? Team
Three things cause this, and they look identical from where you're sitting, so check them in this order.

**Is the Claude desktop app open?** Cowork does its thinking on Anthropic's servers and reaches your machine through that app, so if the app is closed, or it quit in the background, or your machine slept, your files are simply out of reach. Cowork then tells you it can't find them. That's the same wording you'd get if the file really had been deleted, which is what makes this one so confusing. Open the app and ask again.

**Is it the same folder?** Check which folder the Agency Brain app is watching (the app shows it), then in Cowork browse to and pick that same folder. If Cowork and the app are looking at different folders, your work won't reach the team.

**Did it answer, but with something out of date?** This one has no error at all, so it's the one to watch for. Cowork keeps its own copy of files it has already read, and that copy sticks around after the connection to your machine drops. It will quote the old version straight back to you, sounding completely sure. If an answer doesn't match what you know is in the file, open the desktop app, then start a fresh Cowork conversation rather than carrying on in the old one.

The rule underneath all three: "I can't find it" from Cowork means "I can't reach it", and that is not the same as the file being gone. Your files are on your machine and in your team's history the whole time.

        
Cowork won't start on Windows. It says "Missing HCS Services: HNS, vmcompute". What now? Team
That message means the PC is running Windows Home, which can't run Cowork at all. Cowork does its work inside a small virtual machine, and the Windows features it needs (the Hyper-V stack) only ship with Windows Pro, Enterprise, or Education. There's no reliable settings or PowerShell fix on Home.

Three ways forward, cheapest first. One: use Claude Code instead. It runs fine on Windows Home, works on the Claude plan you already have, and points at the same brain folder, so everything syncs exactly the same; all you give up is Cowork's visual layout. Two: upgrade Windows from Home to Pro (a one-off US$99 licence upgrade from Microsoft, no new computer needed), and Cowork then runs on the machine as normal. Three: a Claude Max plan includes Cowork in the browser, which runs in the cloud and skips the Windows problem entirely, but it's the priciest option and the other two are usually the better call.

        
The app says it "can't push your changes up". Is my work lost? Team
No, nothing is lost. That message means your work is safely saved on your machine, but the app couldn't hand it up to GitHub on its last attempt. It keeps retrying every minute or so, and most of the time the cause is a brief internet blip or two teammates saving at the same moment, which clears itself within a few minutes. If it stays up for more than an hour, something real is in the way. First check the app is up to date (it updates itself within a few hours of a release), because current versions fix the common causes on their own, including a too-big file baked into a save. If it still won't clear, grab the app log (Show log in the app menu) and send it to your Scout or Owner, or get in touch with us; recent versions also report the underlying reason to us, so we can usually see exactly what's wrong from our side.

        
Who do I contact when something goes wrong with Agency Brain? Team
Your Scout or Owner first, not Anthropic. They set your agency brain up and can see the GitHub side of things. When you ask, grab a screenshot and the app log (Show log in the app menu) so they can see what happened.

        
What does the Agency Brain icon tell me?
The brain icon really just shows on or off. When the app is running and syncing it's the orange brain, and that's what you'll see almost all the time, including while it quietly syncs in the background. If it looks greyed out, the app isn't running or hasn't been pointed at a folder yet, so click the icon and choose Settings, then "Run setup again…", and point it at your agencybrain folder. For the actual detail, click the icon: the top of the menu tells you in plain words what's happening (syncing and when it last pushed, paused, or needs your attention).

        
I picked the wrong folder during setup, or it isn't where I chose. How do I change it?
Click the brain icon in your menu bar, choose Settings, then "Run setup again…", and point it at the folder you want. That is the way to change it; there is no "Change folder" item in the menu, and this FAQ wrongly said there was until 9 August 2026.

One thing to know before you pick: choose a normal local folder, not iCloud Drive, Dropbox, OneDrive or Google Drive. Those services sync the same files themselves, on their own schedule, and a brain is a git repository, so you end up with two systems moving the same files around and standing on each other. It also explains the odd case where the app ends up using a folder that isn't quite the one you chose, because iCloud in particular relocates and offloads folders behind the scenes. Somewhere like your home folder or Documents is ideal, and your brain is already backed up by being on GitHub, so it does not need a cloud drive for safety.

        
On Windows the install threw scary warnings (SmartScreen, "isn't commonly downloaded"). Did I do something wrong?
No, that's expected. Windows shows warnings that don't mean anything is actually wrong. For the download warning, click the three dots next to it, then Keep, then Keep anyway (click the down arrow on the delete button!). For the SmartScreen screen ("Windows protected your PC"), click the small "More info" text, then "Run anyway". If double-clicking the installer does nothing at all (no box, no error), which can happen on a locked-down or work-managed PC, right-click the downloaded Agency-Brain-Setup.exe, choose Properties, tick "Unblock" near the bottom, click OK, then open it again and it runs first time. Don't click Delete. You also need Git installed (from git-scm.com, choosing the middle PATH option), and then fully restart Claude.
